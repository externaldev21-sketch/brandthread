# iOS permission strings, ATT and privacy manifests

Audited 2026-09-30 against `artifacts/mobile/package.json` and `app.json`.
Automated by `scripts/verify-ios-privacy-manifest.js` (run by
`verify:privacy-manifest:config`) and `scripts/legal-privacy.test.ts`.

## Permission prompts: in context only

No permission is requested at launch. Every `request*PermissionsAsync` call sits
behind a user action (tapping camera, Save, Go live, a notification-worthy
action). Push permission is requested once, after a successful action
(`lib/contextualPushPermission.ts`), never on boot. No pre-permission screens exist.

## App Tracking Transparency

**Not required, and must not be added.** No in-app SDK tracks across apps:
no ad SDK, no IDFA access, no data broker. The Meta and TikTok pixels
(`lib/marketingPixels.ts`) load on the website after cookie consent and never in
the native app. RevenueCat, Sentry, Clerk, Stripe and Agora are service
providers acting for Brandthread. `NSPrivacyTracking` is `false` with no tracking
domains. If an SDK that tracks is ever proposed, remove or replace it rather
than add the prompt.

User Defaults CA92.1, plus the 18 collected data types in
`docs/app-store/privacy-labels.md`.
