## Fixed
- `components/SaveToCollectionSheet.tsx:116-130`: after an account switch while the sheet was open, a failed `getCollections()` for the new account left the previous account's boards listed, and they could be tapped. → `listOwnerRef` records whose boards are in `collections`. `load()` clears the list when the account differs. Test: `components/__tests__/SaveToCollectionSheet.accountSwitch.audit2.test.tsx` (render; failed before: yes)
- `components/SellerHomeCommerceDashboard.tsx:313-336` handleCopyStoreUrl had three problems: it showed the "copied" checkmark even when the clipboard write rejected, that rejection went unhandled, and the 1.2s reset timer was never cleared on unmount. → The clipboard write is now in try/catch. The checkmark (and `firstWeek.storeShared`) happens only after the write succeeds. The timer is held in `copiedTimerRef`, replaced on each copy and cleared on unmount. Test: `components/__tests__/SellerHomeCommerceDashboard.copyRefresh.audit2.test.ts` (source-structure; the dashboard can't render under the shim; failed before: yes, verified against a reconstructed pre-fix copy)
- `components/SellerHomeCommerceDashboard.tsx:~515,~595` (pull-to-refresh): `onRefresh` called `loadSecondaryData()` directly and also bumped `retryTick`, whose effect called `loadSecondaryData()` a second time. Every pull fetched the orders/products/returns/conversations/hub set twice, concurrently and with no ordering guard. → Before bumping, `onRefresh` marks the `retryTick:storeContextTick` pair its own load covers, and the effect skips that one pair. Analytics and AI suggestions still refetch on the bump. The existing contract tests' exact strings are kept. Test: same file as above (failed before: yes)
- `components/products/ProductSellerRow.tsx:45,54`: `rating` and `following` were never reset. A new `sellerId` whose lookups failed kept the previous seller's stars and "Following" state, and signing out kept "Following". → Each effect resets its state before deciding whether to fetch. Test: `components/products/__tests__/ProductSellerRow.idChange.audit2.test.tsx` (failed before: yes)
- `components/products/ProductSaveStatsRow.tsx:19`: a new `productId` (a 404, or still loading) kept showing the previous product's save stats. → `setStats(null)` at the start of the effect. Test: `components/products/__tests__/ProductSaveStatsRow.idChange.audit2.test.tsx` (failed before: yes)
- `components/payouts/HeldForDeliveryRow.tsx:69-90` HeldForDeliverySection: after sign-out the previous account's held amount stayed visible. After an account switch the fetch never re-ran (deps were only `isSignedIn`). → `accountKey` (userId while signed in) resets summary/failed and is added to the focus-effect deps. Test: `components/payouts/__tests__/HeldForDeliverySection.account.audit2.test.tsx` (failed before: yes)
- `components/products/ProductCard.tsx:220`: when `compareAtPriceCents` is 0, `{compare && compare > price && …}` rendered a bare `0` inside the price-row `<View>`. On native that is a "Text strings must be rendered within <Text>" crash. → `compare != null && …`. Test: `components/products/__tests__/ProductCard.zeroCompare.audit2.test.tsx` (failed before: yes)
- `components/checkout/OrderSummarySection.tsx:167-178`: with Thread Cash AND a gift card applied, two "Order total" lines appeared, and both were wrong. The first used `orderTotalCents` (no gift card), the second `totalCents + giftCard` (no Thread Cash). The server (api-server `routes/checkout-intent.ts:267,282`) computes group `totalCents = full − loyalty − threadCash − giftCard (+ tip)`, so the real order total is `totalCents + threadCashCents + giftCardCents`. → One "Order total" line with that value, followed by separate Thread Cash and Gift card lines. Test: `components/checkout/__tests__/OrderSummarySection.orderTotal.audit2.test.tsx` (failed before: yes; Thread-Cash-only and gift-only cases unchanged)
- `components/buy-now/VariantPickerSheet.tsx:103-141`: `load()` had no cancel guard. When the sheet was re-pointed at another product, the earlier product's late response replaced it. → `loadGenRef` generation: only the latest load writes state. Unmount and the `initialProduct` path also bump it, so a stale fetch can't overwrite a provided product. Test: `components/buy-now/__tests__/VariantPickerSheet.loadRace.audit2.test.tsx` (failed before: yes)
- `components/onboarding/launch/AuthScreens.tsx:152-161`: a double tap on "Resend code" while the first resend was in flight sent two codes. → `resendingRef` in-flight guard, released in `finally`. Test: `components/onboarding/launch/AuthScreens.resendInFlight.audit2.test.tsx` (failed before: yes)

A comment the socket delivered while that request was in flight was appended a second time (same id, so a duplicate React key). → New `appendComments()` dedupes by id at both append sites. `poll()` no longer moves the `lastTs` cursor back past a newer socket comment (Date.parse compare; the server returns ISO timestamps). Test: `components/live/LiveAuctionCheckoutViewer.commentDedupe.audit2.test.tsx` (render; failed before: yes)
