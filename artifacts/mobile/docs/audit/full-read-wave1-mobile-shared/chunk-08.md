## Fixes
- `artifacts/mobile/components/products/LaunchTimePicker.tsx:27` — the 28 day chips (values and "Today"/"Tomorrow" labels) were built once at module load. In a session left open past midnight, the picker (product launches, discount active dates) offered yesterday's date as "Today", so a seller tapping "Today" scheduled a launch/discount for a day that has already passed. → chips are now built per render (`dayChips()`). Test: `artifacts/mobile/components/products/__tests__/LaunchTimePicker.audit.test.tsx` (failed before: yes)
- `artifacts/mobile/components/products/LaunchTimePicker.tsx:63` — the `scrollToSelected` prop comment said "Opt-in: on mount, scroll each chip row so the selected chip is in view". The prop does nothing: `revealChip` is never wired (no chip gets a `row`, and `dayRow`/`timeRow` are never attached), and ChipRow's `selectedIndex` scrolls to the selected chip for every caller anyway. → the comment now says the prop is unused and why it stays (callers still pass it). No code removed. Comment-only, no test.
- `artifacts/mobile/components/products/FitChecksStrip.tsx:25` — the effect never cleared `items` when `productId` changed. Moving to a product whose id is not a UUID kept showing the previous product's fit checks indefinitely, and between two UUID products the old strip stayed until the new request finished. → `setItems([])` at the start of the effect, the same as the sibling product-page blocks. Test: `artifacts/mobile/components/products/__tests__/FitChecksStrip.audit.test.tsx` (failed before: yes)
