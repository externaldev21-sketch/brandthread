## Fixes
- `components/ui/ContextMenuHost.tsx:133`: the long-press preview menu had `<View … /> // theme-exempt: neutral context-menu scrim` inside JSX children. That trailing `//` text is a JSX text node: a bare string rendered as a child of `Animated.View`. On iOS/Android that throws "Text strings must be rendered within a <Text> component" as soon as any long-press preview menu opens. On web it renders the literal text. Fix: moved the colour to a module constant `CONTEXT_MENU_SCRIM` with the `// theme-exempt:` comment on that line, which keeps the theme-colour lint exemption intact. Test: `components/ui/__tests__/ContextMenuHost.audit.test.tsx` (renders the host with a context request and asserts no raw strings outside Text). Failed before: yes, it received `" // theme-exempt: neutral context-menu scrim"`.
- `components/ui/MotionPrimitives.tsx:155-179` (CountUpNumber): `fromRef` was updated only when an animation completed. A `value` change mid-animation restarted from the interrupted animation's start, so the count jumped backwards (0→100 interrupted at 88 by 200 restarted at 0). If the new value equalled that old start (0→100, then back to 0), `from === to` returned early and the display stayed stuck at the part-way number (88) for good. Fix: track the number actually on screen (`shownRef`) and start every animation from it. Test: `components/ui/__tests__/CountUpNumber.audit.test.tsx`. Failed before: yes, both cases (`'88'` instead of `'0'`, and `0 < 88` jump back).
- `hooks/useAiCredits.ts:23-46`: the balance was not scoped to the account on screen. (a) After an account switch, `overview` kept showing the previous account's balance until the new fetch landed, and for good if that fetch failed. (b) A slower in-flight response for the previous account called `setOverview` and overwrote the new account's balance. Fix: a `currentUser` ref gates `setOverview`/`setLoading` to the account now shown. A `shownFor` ref clears the overview when the account changes and there is no cache for the new one. The cache stays keyed by userId as before. Test: `hooks/useAiCredits.audit.test.tsx`. Failed before: yes (`500` instead of `7`; previous user's `{balance:3}` instead of `null`).
- `hooks/useBuyerPreferences.ts:35-90`: `invalidateBuyerPreferences()` cleared the cache and forced a re-render, but the load effect's deps (`[uid, load]`) did not change. Every mounted consumer then sat at status `'loading'` with EMPTY preferences until it remounted, so the PDP size badge/auto-select stopped working after an invalidation. Also, a request already in flight before the invalidation still `publish()`ed its stale value, which could land after the fresh one. Fix: the listener's `force` counter (`version`) is now an effect dep so consumers refetch. A module `generation` (bumped on invalidate) drops superseded results and errors. Test: `hooks/useBuyerPreferences.audit.test.tsx`. Failed before: yes (no refetch issued).
- `hooks/useCreditPackPurchase.ts:34-38`: on native, once `rc.purchaseCreditPack` had succeeded (store charge done), a rejected `api.aiCredits.get()` in the balance-poll loop threw into the outer catch. The buyer then got "Purchase failed. Could not complete the purchase. Please try again." and the result was `'failed'`, which invites a second payment. Fix: poll errors are swallowed (`.catch(() => null)`) and the result stays `'purchased'`. Test: `hooks/useCreditPackPurchase.audit.test.tsx`. Failed before: yes (`'failed'`).
- `hooks/useVoiceRecorder.ts:78-150`: `beginRecording` awaits the mic permission prompt and `prepareToRecordAsync` without checking whether the attempt was abandoned meanwhile. If the person cancelled or let go during the prompt (very likely on first use, since the permission dialog terminates the hold gesture), the recorder still started afterwards: live mic, a "recording" pill nobody is holding, and a running timer. After a release (finish), `cancelledRef` was false, so the 5-minute auto-finish would upload and send the voice note. `finish()` during the prompt also computed `tooShort` against a stale/0 `startedAtRef`. Fix: an `attemptRef` bumped by begin, cancel and finish. Begin aborts (and restores the audio mode) if its attempt is no longer current. `startedAtRef` is reset to 0 at begin, and `finish` treats 0 as "never started". Test: `hooks/useVoiceRecorder.audit.test.tsx`. Failed before: yes (`recorder.record` called in both cases).
- `hooks/useSubscriptionPlan.ts:83-145`: every fetch attached `.then(setPlan)` to the shared promise without checking whether that fetch was still current. On a store switch (`subscribeStoreContext` → `invalidatePlanCache`) or account switch while a request was in flight, the previous store's answer could land after the new one. That overwrote `plan` with the other store's plan, so features were gated on the wrong store's plan. Fix: a per-instance `requestRef`; only the latest fetch may set state. Test: `hooks/useSubscriptionPlan.audit.test.tsx`. Failed before: yes (`'starter'` instead of `'pro'`). The existing `hooks/useSubscriptionPlan.test.tsx` still passes.
- `hooks/useFeedVideoPreload.test.tsx` (baseline failing test; the TEST was stale): it counted `expo-video` `createVideoPlayer` calls. The hook deliberately warms upcoming videos by fetching bytes (`preloadVideoBytes` + AbortController, "Warms bytes and posters without allocating decoders"), so it never creates a player, and "warms the upcoming videos normally" could never pass. Updated the test's `@/lib/videoPreload` mock so it records `preloadVideoBytes` calls. Both assertions are unchanged: warms > 0 normally, nothing with data saver. Now passes.
- Comment fixes (no test needed):
  - `components/ui/Button.tsx:142-147`: the comment said "no android_ripple". The Pressable does set a bounded, theme-tinted `android_ripple`, which `tests/no-outer-focus-ring.test.ts` requires. Comment now describes it.
  - `components/ui/TopToast.tsx:37`: "Without it [onDismiss] the toast never hides itself" was false, because the timer and swipe both call `setHidden(true)` regardless.
  - `hooks/useQueryResult.ts:18-19`: the default `isEmpty` was documented as "falsy or empty array/string". The code treats only null/undefined and `[]` as empty, so `0`, `''` and `false` are 'loaded'.
  - `hooks/useSellerTabBarInset.ts:12-14`: "Returns 0 when no seller bar is on screen" was false. It returns the safe-area floor, as its own test asserts.

Every current caller passes a static `variant="underline"` or none, so it is latent. Fixing it means splitting the pill branch into its own component (a refactor).
- `hooks/useResponsive.ts:4-11,45-51`: the header says the classes are keyed off the shortest side "so rotation doesn't change class". `classify` uses `width` for compact/regular/largePhone, so a regular phone in landscape becomes 'largePhone', and the `regular && landscape` branch is nearly unreachable. Changing either side changes grid column counts on rotated phones, which is a product decision.
- `components/ui/AppleEmoji.tsx:31-39`: the Twemoji filename keeps U+FE0F (e.g. `2764-fe0f.png`), but Twemoji files omit it for most emoji, so many emoji 404 and fall back to the platform glyph. This degrades gracefully. Fixing it needs the Twemoji naming rules; not verified per emoji.
- `components/ui/IconButton.tsx:66-89`: the comment says "Disabled is a solid gray glyph, not a faded one", yet `DISABLED_OPACITY` is also applied to the whole button. The look is deliberate design, so not changed.
- `components/ui/ActionSheet.tsx:73,174-177`: the host registers via `useMemo` and never unregisters on unmount, so a stale `hostOpen` would remain if the root host ever unmounted. It is mounted once at the root, so not reachable today.
- `hooks/useProductDraw.ts:29-44`, `hooks/useStoreGiftCards.ts:13-19`: neither guards against a response for a previous `productId`/`sellerId` landing after the id changes on the same instance. Their only callers get the id from route params (a new screen per id), so I could not show it is reachable.
- `hooks/useSellerInsight.ts:14`: a non-preview caller that is loaded but has no userId stays `loading: true` forever. Seller screens are auth-gated; not changed.
