## Fixes
- `artifacts/mobile/lib/previewOrderEdits.ts:19-28`: crosschunk entry verified. `loadPreviewSellerOrder` returned a generated demo order (`getGeneratedSellerOrder`) and any saved session edit for any `preview-demo-order-*` id with no gate. A real signed-in seller opening such an id in order-detail or fulfill-batch saw a made-up order. (`previewSellerOrders.ts` says "callers gate on isPreviewDemoMode()", and the sibling `getPreviewSellerOrder` already does.) Fix: `|| !isPreviewDemoMode()` at the top of the function, so the generated branch and the edits map are both covered. Tests: `artifacts/mobile/lib/previewOrderEdits.audit.test.ts` (failed before: yes) and the existing `lib/__tests__/demoOnlyFallbacks.test.ts` case "order-detail only renders a generated demo order inside a preview" (failed before: yes, passes now).
- `artifacts/mobile/lib/previewSellerInsights.ts:45`: the 'week' bucket starts were built as `new Date(y, m, start.getDate() + i)`, which uses the current month with the start day's date. When the week began in the previous month (for example Thu Oct 1 2026, week starting Sun Sep 27), the buckets came out as Oct 27–31, which is in the future and the wrong month, so every week-range seller report chart was mislabelled. Fix: build from `start`'s own year and month (same as the 'all' branch). Test: `artifacts/mobile/lib/previewSellerInsights.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/previewSellerOrders.ts:159,216`: demo order numbers were `(day)*10 + i + 1000`. A day can have up to about 14 random orders (i ≥ 10 runs into the next day's numbers), and the two world orders used i = 900/901 (which runs into the numbers of the day 90 days later). Measured: 2,764 of 9,677 demo orders shared a BT-number with a different order, so Orders tab and order search showed the same number twice. Fix: `orderNumberFor(idx, slot)` with 100 numbers per day (random orders in slots 0..~13, world orders in slots 90/91). Ids, tracking numbers and `getGeneratedSellerOrder` are unchanged. Test: `artifacts/mobile/lib/previewSellerOrders.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/previewSellerDrops.ts:48`: the drop-hype series dates were `now - k*24h`. Across a DST change this skips or repeats a calendar day. Example: America/New_York, Mar 9 2026 00:30, the series went …Mar 6, Mar 7, Mar 9, so every earlier point was labelled one day early. Fix: step back in local calendar days (`new Date(y, m, d - k)`), and remove the now-unused `DAY_MS`. Test: `artifacts/mobile/lib/previewSellerDrops.audit.test.ts` (sets TZ; failed before: yes).
- `artifacts/mobile/lib/previewSellerFreshStore.ts:92-103`: the hydration race. If the preview seller added a discount, started a Live or edited the storefront before the AsyncStorage read resolved, the read replaced `state` wholesale with the older saved session and then `notify()` persisted it. The new item disappeared on screen and from storage. Fix: if `state` was mutated before hydration, `mergeOverSaved` keeps the live rows on top, appends saved rows with other ids, and keeps the live storefront if it was edited. The merged result is persisted. Test: `artifacts/mobile/lib/previewSellerFreshStore.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/revenueCat.native.tsx:125-165`: the start-up effect's async `start()` only checked `sessionGuard.isCurrent(generation)`. An unmount does not bump the generation, so if the provider unmounted while `accountSetup`/`getCustomerInfo` was in flight, `start()` still added the SDK customer-info listener after cleanup had run, and that listener was never removed. It also called setState after unmount. Fix: a `disposed` flag set in the cleanup, with `live()` (`!disposed && isCurrent`) checked before adding the listener, inside the listener, and before the state updates. Test: `artifacts/mobile/lib/revenueCatProvider.audit.test.ts`. This is a source-structure test, the last resort: the provider needs the native store SDK, Clerk and the API client, which do not render under the Vitest shims. Failed before: yes.
- `artifacts/mobile/lib/previewInboxData.ts:519`: comment fix. It cited "preview-msg-03-2" as the buyer-side voice bubble, but no such message exists; the buyer voice bubble is `preview-msg-07-3`. Comment only, no test.
- `artifacts/mobile/lib/previewProducts.ts:157`: comment fix. It said "adaptApiProduct above", but that function is not in this file; it lives in `services/cartService.ts`. Comment only.
- `artifacts/mobile/lib/previewStories.ts:15-17`: comment fix. It claimed the module is gated by `isPreviewInboxEnabled()`. The real gates are `isPreviewStoriesEnabled()` (= `isPreviewCatalogEnabled()`) plus `isPreviewDemoMode()` for the seeded rows. Comment only.
