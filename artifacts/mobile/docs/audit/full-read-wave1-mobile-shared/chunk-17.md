## Fixes
- `artifacts/mobile/lib/money.ts:53` — `formatCents(-0)` gave "-$0.00": Intl formats negative zero with a minus, so any `a - b` / `-x` that lands on 0 showed a phantom charge. This was the baseline failure "keeps formatCents unchanged for zero" (the test was right; the code was wrong). → -0 is turned into 0 before formatting. Test: `artifacts/mobile/lib/money.test.ts` (existing test; failed before: yes)
- `artifacts/mobile/lib/calls/CallSessionContext.tsx:202` — Hanging up during "Calling…" (before `provider.start` resolved) only ended the local `pending_` session. The server call that `start` created was never ended, so the callee's phone kept ringing and the caller's Agora channel stayed joined (mic open) until the ring timeout. → Pending ids that were hung up are tracked in a ref. When `start` resolves for one, `provider.end(callId,'cancelled')` is called and no subscription is made. Test: `artifacts/mobile/lib/calls/__tests__/CallSessionContext.audit.test.tsx` (failed before: yes)
- `artifacts/mobile/lib/calls/CallSessionContext.tsx:200` — On sign-out or an account switch, `useApi` changes, so the agora provider is rebuilt and the old one is disposed. But `session` and `logsByConversation` were kept. The previous account's call stayed frozen on screen (no subscription left to end it), and its call-log cache stayed too. → An effect keyed on `authUserId` tears down the subscription and clears the session, the pending-cancel set and the logs. Test: same file (failed before: yes)
- `artifacts/mobile/lib/createPost/useDeviceMedia.ts:413` — `loadPage` returned early while `busy` was set. So picking an album while Recents was still loading cleared the grid and never loaded the album, and the late Recents page then filled the grid under the new album's name. → Each reset bumps a generation. A reset is never skipped, and a page that resolves for an older generation is dropped. Test: `artifacts/mobile/lib/createPost/__tests__/useDeviceMedia.audit.test.tsx` (failed before: yes)
- `artifacts/mobile/lib/firstRunTips/storage.ts:532` — Turning "Skip all tips" off in Settings did not clear the pre-sign-in ('anon') skip record. That record is OR-ed into every read, so the setting read as on again, and the next `syncFirstRunTipsFromServer` re-sent `skipAll()`, turning it back on on the server. → When turning it off, the anon record is cleared too, and restored if the server call fails (same idea as `replayAllTips`). Test: `artifacts/mobile/lib/firstRunTips/storage.audit.test.ts` (failed before: yes)
- `artifacts/mobile/lib/listing/publishListing.ts:300` — Editing a no-size listing into several sizes added new sized variants. The old no-size ('' key) variant was skipped by the `if (size && ...)` zeroing loop, so it kept selling its old stock next to the new sizes. → Variant ids actually updated are tracked, and every existing variant id the form no longer uses is set to stock 0. Test: `artifacts/mobile/lib/listing/publishListing.audit.test.ts` (failed before: yes)
- `artifacts/mobile/lib/live/apiLiveProvider.ts:271` — A comment delivered over the `/ws/live` socket while a catch-up poll was in flight was emitted twice. Poll results were never checked against or added to `seen`, and `since` could also move backwards. The feed pager's chat showed the line twice. → Poll comments are filtered by and recorded in `seen`, and `since` only moves forward. Test: `artifacts/mobile/lib/live/__tests__/apiLiveProvider.audit.test.ts` (failed before: yes)
