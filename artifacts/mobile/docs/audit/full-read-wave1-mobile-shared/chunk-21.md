## Fixes
- `artifacts/mobile/lib/setupStore.ts:111` — `DEFAULT_TASKS` listed `connect_payments` ("Set up payments") twice. This defect is user-visible. The seller checklist (app/setup.tsx, `key={task.id}`) showed the payments row twice, with a duplicate React key. Progress also counted payments twice: 9 required tasks instead of the server's 8 (api-server lib/sellerSetupChecklist.ts SETUP_TASK_IDS), so after connecting Stripe the bar read 2/9 = 22%, and every percentage was wrong. → Removed the duplicate entry. Test: `artifacts/mobile/lib/setupStore.audit.test.ts` (failed before: yes, 2/2).
- `artifacts/mobile/lib/setupStore.test.ts:44-93` — this test encoded the duplicate: "keeps all ten tasks", 9 required, 11% for 1 done. It is a stale test of a bug, not a deliberate product choice, because there are only 9 SetupTaskIds and the server has 9 tasks, 8 of them required. → Updated it to 9 tasks / 8 required / 13% (1 of 8, rounded). Test: same file (passes).
- `artifacts/mobile/lib/shareActions.ts:40` — on web, `copyText`/`copyLink` used `navigator?.clipboard?.writeText?.(text)`. When the Clipboard API is missing (insecure origin, old browser) the optional chain does nothing, yet the code still showed "Link copied" and returned true, so the user believed a link was copied when it was not. → It now throws when `writeText` is unavailable, so the failure alert shows and the function returns false. Test: `artifacts/mobile/lib/shareActions.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/shareLinks.ts:91,109` — `parseShareLink` accepted look-alike hosts because there was no host boundary after `brandthread.app` (both the SHARE_ORIGIN prefix check and the HOSTS regex). Examples: `https://brandthread.app@evilshop/p/<id>` (the real host is evilshop) became an in-app product route, and `https://brandthread.app@novagoods` became a store. The function's contract and test say foreign hosts return null. → It now requires `/`, `?`, `#` or the end of the string right after the origin. Test: `artifacts/mobile/lib/shareLinks.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/shareProfile.ts:58` — `parseProfileDeepLink` (QR scanner) had the same flaw: the optional `\/?` meant `https://brandthread.appu/jordan` matched as a Brandthread profile. → The https branch now requires `/` after the host; `brandthread://u/x` and `brandthread:///u/x` still work. Test: `artifacts/mobile/lib/shareLinks.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/sellerControlCenter.ts:127` — the Studio "Activity" item's description said "Recent orders, messages and updates". /seller-activity deliberately excludes orders and messages (lib/sellerActivity.ts: "Orders, payouts and inventory alerts stay in Orders; they are not Activity"). The copy was false, and searching the hub for "orders" or "messages" surfaced Activity. → Now "Likes, comments, mentions and new followers". Test: `artifacts/mobile/lib/sellerControlCenter.audit.test.ts` (failed before: yes).
- `artifacts/mobile/lib/sellerPaymentStatusCache.test.ts:127` — "does not cache failed requests" timed out (5s). It is on the baseline failing list. Cause: a deliberate product change, the one quiet auto-retry for transient read failures in lib/api.ts doRequest (`retryQuietly`, AUTO_RETRY_DELAY_MS from lib/requestResilience.ts). Under fake timers the 600ms retry timer never fired, and the single mocked rejection would have been retried anyway. The code is correct (a failure still is not cached), so the test was stale. → The test now rejects both attempts, advances fake timers, asserts the call rejects after 2 fetches, then asserts the next call fetches fresh (3rd fetch). The assertion is not weakened. Test: same file (failed before: yes, timeout).
